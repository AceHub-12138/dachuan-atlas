6. **关系探索可用**：模块 → 文件 → 符号渐进浏览；中文模块名、中文节点名、文件名、符号名搜索；按类型、审核、证据、方向筛选。以语音模块为例，浏览器麦克风 23 条关系；数据模块的“大屏舞台”筛出 4 条 AI 复核关系。
7. **独立 Google Chrome 实测通过**：Chrome 155 本地文件导入、四模块详情、关系搜索/筛选、导出后重新导入全部成功；控制台 0 error，页面无 `.atlas.json` 网络请求。
8. **回归通过**：73 项测试（8 个文件）、TypeScript 0 error、构建通过、默认构建安全门禁通过；演示模式完整 100.1 FPS、低动态 99.9 FPS、静态 `rafActive:false`。Canvas 引擎未改动。

## 2. 安全边界修正（阶段 A1）

### 2.1 修正前的问题

P1.0 的状态：

| 问题 | P1.0 状态 | 风险 |
| --- | --- | --- |
| 真实快照位置 | `public/architecture/nexus/*.atlas.json` | 任何构建都会复制到 `dist`，可直接下载 |
| 前端代码 | 模块规则、33 条中文注释、源码路径参与主 bundle | 即使移除快照，内部路径仍会进入公开 JS |
| 默认加载 | 顶栏切换会 fetch 已打包快照 | 真实架构默认随站点发布 |
| 审核显示 | 13 条标为“人工核实” | 实际只有 Agent 源码记录，语义不实 |

### 2.2 修正后的结构

```text
local-data/nexus/*.atlas.json      # 真实数据，.gitignore，不进入 public/dist
            │ 用户明确选择文件
            ▼
浏览器文件导入（仅 ATLAS 标准数据）
            │
            ▼
内存中的 AtlasDataset → 四模块详情 / 关系探索
```

- `public/` 现在只保留 `atlas-mark.svg`。
- `dist/` 只有 HTML、CSS、JS、字体与图标；**没有** `.atlas.json`。
- 默认访问始终是演示数据；不自动 fetch 真实快照。
- `local-data/` 已加入 `.gitignore`；克隆项目后不会带上真实快照。
- CLI 拒绝把真实快照写入 `public/`；默认输出为 `local-data/nexus/`。
- 当前项目**不是 Git 仓库**，因此没有历史提交需要改写；P1.0 的 `dist/` 是可再生成产物，已重新构建。若未来初始化 Git，应确认 `local-data/` 不被跟踪（已在 `.gitignore`）。

## 3. Schema 1.1 与兼容性（阶段 A3）

### 3.1 新增内容

`atlas.architecture` 从 `1.0.0` 升到 `1.1.0`，均为向后兼容的扩展：

| 位置 | 新增 |
| --- | --- |
| `AtlasReview` | `method`（审核方式）、`actor`（主体）、`evidence[]`（审核依据）；保留 `status/reviewer/reviewedAt/note` |
| `AtlasModuleRecord` | `reviewRecord`、`summary`、`responsibilities[]`、`keyComponents[]`、`gaps[]` |
| `AtlasModuleComponent` | 代表对象的符号、文件、行号、中文名、职责、审核记录 |
| `AtlasDiagnostics` | `reviewCounts`：AI 复核 / 人工 / 直接提取待核实 / 推断待核实 |
| `AtlasDataset` | `schemaMigratedFrom`：旧版迁移来源 |

审核方式枚举：

- `graphify-extracted`
- `graphify-inferred`
- `ai-source-review`
- `human-review`
- `unverified`

### 3.2 1.0 兼容与迁移

`parseAtlasDataset` 接受 `1.0.x` 与 `1.1.x`，拒绝 `1.2+` 与 `2.x`。

迁移规则：

1. 1.0 的节点/关系/模块补齐 `method/actor/evidence`。
2. 旧版 `verified` 且 reviewer 为 `P1.0 人工核对` → `ai-source-review`，主体改为 P1.0 施工 Agent，备注说明来源修正。
3. 旧版 `verified` 但没有可识别主体 → 降级为 `unverified`，避免继续冒充已核实。
4. 旧版模块补齐 `summary`（取 description）、`responsibilities`、`gaps`（取 notes）、`keyComponents`（从已注释节点派生最多 5 个）。
5. 旧版 `reviewCounts` 缺失时根据迁移后的关系重新计算。
6. `schemaMigratedFrom` 记录原版本；提交、节点、关系、证据不改写。

测试覆盖：`dataset.test.ts` 构造 1.0 数据，验证节点/关系数量不变、审核迁移、模块详情补齐、`reviewCounts` 生成；1.2 版本被拒绝。

### 3.3 未改变的事实

- 原始 `EXTRACTED` / `INFERRED` 保留在 `evidenceType`；
- `confidence`、`sourceRelation`、`sourceIndex` 保留；
- 提交 SHA、生成时间、清单校验、节点 ID、源码定位不变。

1. **它是什么**：普通用户可理解的一句话；

## 6. 真实关系探索（阶段 C）

### 6.1 渐进式浏览

- 模块下拉：四个模块；
- 文件列表：按模块聚合，单个模块最多 56 个文件；
- 符号列表：选中文件后才加载该文件符号；

### 6.2 搜索与筛选

搜索支持：

- 中文模块名（如“语音”）；
- 已收录中文节点名（如“浏览器麦克风”）；
- 原始文件名（如 `microphone.ts`）；
- 原始符号名（如 `createVoiceOrchestrator`）；
- 结果上限 30，避免大列表。

筛选支持：

- 类型：调用 / 导入 / 包含 / 其他；
- 审核：AI 源码复核 / 独立人工审核 / 待核实；
- 证据：EXTRACTED / INFERRED / AMBIGUOUS；
- 方向：出 / 入。
