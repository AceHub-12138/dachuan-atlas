```powershell

  "$env:USERPROFILE\Documents\DACHUAN-ATLAS-private-backups\p14-final-20261021\atlas-p14-final-20261021.bundle"

```

应该看到 P1.4 的提交记录，`git status` 显示干净工作区。

### 4.2 放回真实数据（关键修正）

**必须先创建目标目录。** `Copy-Item -Recurse` 不会可靠地替你创建不存在的目标 `local-data`；在部分 PowerShell 版本上会报 “Cannot find path” 或只复制出一层错误结构。

```powershell
$project = "$env:USERPROFILE\Documents\DACHUAN ATLAS"
$dataSource = "$env:USERPROFILE\Documents\DACHUAN-ATLAS-private-backups\p14-final-20261021\local-data-p14-final-20261021"

# 1. 先显式创建目标目录
New-Item -ItemType Directory -Force -Path "$project\local-data" | Out-Null

# 2. 再复制目录内容（注意结尾的 \*）
Copy-Item -Path "$dataSource\*" -Destination "$project\local-data" -Recurse -Force
```

确认文件在项目内、但**不在** `public\` 或 `dist\`：

```powershell
Get-ChildItem -Recurse "$project\local-data" | Select-Object FullName
```

至少应看到：

```text
...\local-data\nexus\nexus-2026-10-20-2584284.atlas.json
...\local-data\nexus\flows\voice-request-to-overlay.flows.json
...\local-data\nexus\explanations\module-explanations.json
```

如果看到 `...\local-data\local-data-p14-final-20261021\...`，说明复制层级错了；删除后重新按上面两条命令执行。

## 5. Windows 路径与数据包规则

| 规则 | 说明 |
| --- | --- |
| 数据中的路径统一用 `/` | ATLAS 会把 `\` 归一化为 `/`；数据集内不允许绝对路径 |
| 不要写 `C:\Users\...` | 绝对路径会被拒绝（`ATLAS_DATASET_PATH_LEAK`） |
| 不要把项目放在 `public\` | 真实快照只能放 `local-data\`，并通过页面导入 |
| 不要把 `local-data` 提交到 Git | `.gitignore` 已排除；不要用 `git add -f` 绕过 |
| 复制前先建 `local-data` | 见 4.2；这是 P1.3 指南的缺陷修正 |
| 不要用 OneDrive / 网盘自动同步内部数据 | 除非公司明确批准并加密；默认只放加密移动介质 |
| bundle 与 local-data 分开复制 | bundle 不含真实数据；两者都要有才能完整恢复 |
| 导出的 `.atlas.json` 仍是内部数据 | 含内部符号和相对路径，不要上传或发到聊天工具 |

### 5.1 PowerShell 命令小抄

```powershell
# 查看 Node / npm / Git 版本
node -v
npm -v
git --version

# 计算 SHA-256
Get-FileHash -Algorithm SHA256 "文件路径"

# 创建目录
New-Item -ItemType Directory -Force -Path "目录路径" | Out-Null

# 从 bundle 克隆
git clone "bundle 路径" "目标目录"

# 复制真实数据（先建目标目录）
New-Item -ItemType Directory -Force -Path ".\local-data" | Out-Null
Copy-Item -Path "数据源\*" -Destination ".\local-data" -Recurse -Force

# 安装依赖 / 测试 / 构建
npm ci
npm test
npm run build
npm run verify:build

# 本地预览
npm run preview
```

## 7. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `Copy-Item` 报 “Cannot find path” | 目标 `local-data` 不存在 | 先执行 `New-Item -ItemType Directory -Force -Path ".\local-data"` |
| `local-data` 下多出一层同名目录 | 复制时用了目录本身而不是 `\*` | 删除错误层级，使用 `Copy-Item "$dataSource\*"` |
| `git clone` 报 “not a git repository” | bundle 路径写错或文件损坏 | 重新复制 bundle，校验 SHA-256 |
| `npm ci` 失败 | Node 版本过低、网络/镜像问题 | 用 Node 22 LTS；按公司规范配置 npm 镜像 |
| `npm run build` 报 TypeScript 错误 | 依赖未安装完整 | 删除 `node_modules` 后重新 `npm ci` |
| 导入报 `ATLAS_DATASET_PATH_LEAK` | 数据集被手工改了绝对路径 | 恢复原始 `.atlas.json`，不要手工改路径 |
| 导入报 `ATLAS_DATASET_CROSS_REPO_INVALID` | 跨仓库关系缺少接口证据或运行时矛盾 | 不改数据硬闯；回到 Schema 1.4 规则补证据或保留候选 |
| 页面没有真实连线 | 没有导入快照，或仍在演示模式 | 通过右上角数据徽标导入；不要期望默认构建带真实数据 |
| `verify:build` 失败 | `dist` 里混入了真实数据 | 删除 `dist` 重新构建；检查是否把 `.atlas.json` 放进了 `public` |
