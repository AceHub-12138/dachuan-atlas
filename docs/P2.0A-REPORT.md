## 1. 本轮结论

P2.0-A 完成了“Graphify 产物 → CRM 独立 ATLAS 数据集”的本地管线：

- CRM 使用独立 `repository.id='crm'`、独立 `snapshotKey`、独立模块定义；
- 导入前核对 `graph.json`、`snapshot-manifest.json`、`GRAPH_REPORT.md` 的仓库身份、
  完整提交 SHA、扫描/生成时间与逐文件 SHA-256；
- 缺少可靠信息时只写 `unknown/partial`，不把当前工作树或猜测当成历史事实；
- 模块只按 profile 的路径/职责规则归类，未匹配节点保持未分类；
- 所有静态关系保持 `intra-repository` + `runtimeScope=unknown`，
  没有运行时证据就不升级；
- 跨仓库关系必须有接口/协议证据与复核记录，证据不足直接拒绝；
- 合成 CRM 导入失败不影响 NEXUS 历史快照或演示模式；
- NEXUS 基线保持 1,390 节点 / 3,170 关系 / 四模块 / 3 组模块对 / 48 条模块间关系 /
  7 个概念步骤 / 4 个静态衔接 / 2 个缺口。

本轮没有扫描 CRM / Electron，没有修改 NEXUS、CRM 或 Electron 的业务源码，
没有进行新的视觉开发，也没有创建远程 Git 仓库。

### 3.2 NEXUS 兼容性

`adaptGraphify()` 保留为 NEXUS 兼容入口，行为不变；新增
`adaptGraphifyWithProfile()` 供 CRM 使用。NEXUS 的四个模块、中文注释、
AI 复核关系清单、coverage notes 没有进入 CRM profile。

CRM profile 禁止使用 `data / voice / animation / canvas` 四个模块 ID；

### 数据边界说明

P2.0-A 的 CLI 是本地确定性代码，不会把数据发送到网络。但施工 Agent 本身运行在
云端模型上；如果用户让 Agent 直接读取真实 CRM 源码、内部符号、Graphify 原始产物
或路径，内容会进入模型调用上下文。真实接入前必须按
`docs/P2.0B-PREFLIGHT.md` 的“数据传输边界”二选一：本地人工执行，或明确授权。

## 7. 需要用户授权的步骤

1. 指定真实 CRM 本地目录与允许读取范围；
2. 提供该目录下的 Graphify 历史产物、完整提交 SHA、扫描/生成记录；
3. 提供 CRM 自己的模块 profile（模块 ID、路径规则、职责、审核记录）；
4. 确认运行时边界证据或接受全部 `unknown`；
5. 确认 NEXUS ↔ CRM 接口清单与复核人；
6. 明确是否允许 Agent 接触真实数据（否则由用户本地运行 CLI，只提供脱敏统计）；
7. 指定 Windows 实机与异机备份的验收安排。

在这些授权完成前，不进入 P2.0-B。
