## 4. 动效模式与资源降载

| 验收项 | 方法 | 实测结果 |
| --- | --- | --- |
| 完整模式 | 点击「完整」并观察 | rAF 连续运行，星空/光流/核心动画正常 |
| 低动态模式 | 点击「低动态」 | 动画速度降至约 0.46 倍，粒子减少，流星停止，CSS 环境动画变慢 |
| 静态模式 | 点击「静态」 | Canvas 连续 rAF 停止，最后一次静态帧保留；CSS 粒子/星云动画 `none` |
| 静态模式下悬停 | 静态模式移动到 NEXUS | tooltip 与强调状态仍然出现；不恢复连续 rAF |
| 窗口失焦 | 合成 `window.blur` 事件，等待 2.3 秒 | 渲染循环降至约 19.6 FPS，CSS 环境动画 `paused` |
| 恢复焦点 | 合成 `window.focus` 事件 | 恢复 100 FPS，CSS 动画 `running` |
| 页面不可见 | 代码监听 `visibilitychange` | 隐藏时取消 rAF；可见时按当前模式恢复（代码审查） |
| 减少动态偏好 | 读取 `prefers-reduced-motion` 决定首次模式 | 已实现为首次进入静态模式；本轮未在系统辅助功能层模拟该媒体查询做二次实测 |

## 6. 性能实测

### 6.1 测量方式

1. 使用页面内 `requestAnimationFrame` 收集帧时间戳；
2. 计算平均 FPS 和 95 百分位帧间隔；
3. 同时读取 `AtlasScene` 内部的 Canvas 绘制耗时与 95 百分位；
4. 场景内部指标每秒汇总一次，通过 `window.__ATLAS_METRICS__` 暴露；
5. 截图为另一时刻的实际浏览器截图，不作为性能叠加结果。

### 6.2 样本结果

| 场景 | 分辨率 | 采样时长 | rAF 样本 | 平均 FPS | 95% 帧间隔 | 平均 Canvas 绘制 | 95% Canvas 绘制 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| 首页，完整动效 | 1920×1080 | 3.2 s | 319 | 100 | 11 ms | 1.27 ms | 2.4 ms |
| 首页，完整动效 | 2560×1440 | 3.2 s | 318 | 100 | 11 ms | 1.31 ms | 2.3 ms |
| 首页 → NEXUS 过渡 | 3840×2160 | 2.4 s | 241 | 100 | 11 ms | 0.75 ms | 0.9 ms |
| 语音详情打开 | 1920×1080 | 1 s | — | 100.1（场景内部） | — | 0.66 ms | 0.8 ms |
| 低动态 | 1920×1080 | 2.2 s | — | 100 | — | 0.59 ms | 0.7 ms |
| 窗口失焦 | 1920×1080 | 2.3 s | — | 19.6 | — | 1.15 ms | 2.0 ms |
| 静态模式 | 1920×1080 | — | 0 | 连续 rAF 停止 | — | — | — |

说明：

- 测试显示器刷新率为 100 Hz，因此 100 FPS 是上限。
- 帧间隔 95 百分位最高为 11 ms，对应约 91 FPS 的节奏；距离 60 FPS 的 16.7 ms 预算仍有明显余量。
- Canvas 绘制耗时是 JS 端每帧绘制调用耗时，不包含浏览器 GPU 合成、窗口合成等完整链路，不等同于专业性能工具采集的完整 frame time。
- 不同运行时刻的采样会有小幅波动；上表为本次验收的实际记录，不推断其他设备表现。

### 6.3 性能优化措施

- 粒子、星点与光晕通过缓存离屏纹理绘制，避免在高频循环中反复创建复杂渐变。
- 关系曲线在初始化时预采样为点集，不在每帧重新计算拓扑。
- 使用可重复的固定随机种子生成星场，避免每次 resize 产生突兀变化。
- 限制 DPR 与 Canvas 最大边长，避免 4K 高 DPI 下的乘法像素填充。
- 失焦和页面不可见时降载；静态模式停止连续 RAF。
- 所有定时器、RAF、ResizeObserver 与事件监听器都在场景销毁或组件卸载时清理。

## 8. 未完成的验收项

以下项目必须如实标记为未完成，不能视作已通过：

1. **Windows 实机运行与性能测试 — 待 Windows 验收。**
2. **独立安装的 Google Chrome / Microsoft Edge 测试 — 待独立浏览器验收。**  
   本轮只验证了 Chromium 146 内核，不能把它等同于所有 Chrome/Edge 版本。
3. **物理 2560×1440 / 3840×2160 显示器验收。**  
   本轮使用浏览器视口渲染，不是物理大屏。
4. **系统级「减少动态效果」辅助功能验证。**  
   代码已实现初始偏好检测，但本轮没有在操作系统层面切换该设置进行实测。
5. **专业 GPU 性能分析。**  
   未使用 Chrome Tracing、Spector.js 或其他专业 GPU 采样工具；本报告中的 Canvas 绘制耗时不等于完整 frame time。
6. **跨浏览器视觉一致性。**  
   Safari / Firefox 不在本轮验收范围。

## 9. 结论

P0 原型在本次 macOS + Chromium 146 环境中完成了系统宇宙、NEXUS 模块星系和语音交互详情的完整可体验流程；三档动效、失焦降载、三种目标分辨率布局和录屏均已完成。本文数据作为 P0.1 优化的对照基线保留。

P0.1 的视觉改动与同环境性能对照见 [P0.1-REPORT.md](P0.1-REPORT.md)。Windows 与独立 Chrome/Edge 的兼容性仍为待验收状态。
