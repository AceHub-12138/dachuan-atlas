## 1. 一句话结论

P2.0 只能接入**一个明确的 CRM 历史快照**，使用 CRM 自己的模块定义和独立快照标识；跨仓库关系必须是经过复核的接口/协议证据，不能从目录或命名相似推断。NEXUS 现有四模块星图与 48 条关系必须保持不变。

## 3. 数据层前置条件

### 3.1 仓库与快照

- 一个 CRM `AtlasDataset`，主仓库 `crm`，独立 `snapshotKey`，例如 `crm@<commitShort>@<generatedAt>`。
- `snapshot.history=true`；`snapshot.atlasSchemaVersion` 记录生成时版本，不冒充当前版本。
- `scannedAt` 没有真实记录时保持 `null`，不能用 `generatedAt` 或 `importedAt` 代替。
- 节点 ID：`crm:<path>#<symbol>`；不与其他仓库共用节点 ID。
- 关系 ID 在 CRM 快照内唯一；多快照索引用 `scopedRelationId()`。

### 3.2 模块定义

- 每个 CRM 模块必须写 `repository='crm'`、`system='crm'`。
- 模块 ID 在数据集内唯一；建议使用领域名（如 `customer`、`order`、`contract`、`receivable`、`shipment`），不要复用 NEXUS 四模块 ID。
- 节点的 `moduleId/moduleIds` 只能引用同一仓库模块；主模块在 `moduleIds` 首位。
- 模块归类只看源码路径与职责，不读取 Graphify Community。
- 未核对的中文名称与职责保持 `null`，不机器翻译。

### 3.3 关系与运行时

- 仓库内静态关系：`repositoryScope='intra-repository'`；没有边界证据时 `runtimeScope='unknown'`。
- CRM 服务端与 Web 前端同仓库但跨运行时：`intra-repository` + `cross-runtime`。
- 只有 trace、日志、协议测试、集成测试或运行时观察才能设 `runtimeVerified=true`；AI 源码复核不够。
- 每条 `runtimeEvidence` 必须带 `kind`，并绑定已登记提交。

### 3.4 跨仓库关系

- 与 NEXUS 的接口关系必须 `repositoryScope='cross-repository'`。
- 必须提供 `interfaceEvidence`（API 契约、协议 schema、包清单、配置绑定、契约/集成测试）并经过 AI 或人工复核。
- `runtimeScope` 独立判定：跨仓库不等于跨运行时；有真实调用证据才设 `cross-runtime`，有运行时记录才设 `runtimeVerified=true`。
- 未审核候选不得进入 `confirmedCrossRepositoryRelations()`。

## 4. 导入与展示前置条件

1. CRM Graphify 原始数据先在本地 CLI 转换为 `crm-<snapshot>.atlas.json`；浏览器只接收标准数据。
2. 真实 CRM 数据只放 `local-data/crm/` 或由用户本地导入；不得进入 `public/`、`dist/`、Git 仓库或云端模型。
3. 导入失败不得影响 NEXUS 当前数据集；演示模式和 NEXUS 历史快照必须仍可切换。
4. CRM 星图使用独立仓库星群 / 仓库切换器；不得把 CRM 节点画进 NEXUS 四模块轨道。
5. 跨仓库关系单独显示，边详情必须能回到 `interfaceEvidence` 与审核记录；没有证据不画线。
6. NEXUS 投影必须保持 4 模块 / 3 组有向模块对 / 48 条关系 / 7 个概念步骤 / 4 个静态衔接 / 2 个缺口。

## 5. 验收门槛

P2.0 只有在以下全部成立时才能标记“CRM 已接入”：

- [ ] 用户书面确认扫描范围与本地 Graphify 产物；
- [ ] CRM 快照有真实提交 SHA 或明确 `unknown/partial`；
- [ ] `--git-repo` 核实提交为 commit 对象，且清单文件与历史树一致；
- [ ] 清单内部一致性与 Git 历史核实都通过时才标记 `complete`；否则明确 `partial`；
- [ ] 哈希、字节数、提交、仓库身份、时间、路径或符号链接冲突时硬失败；
- [ ] CRM 模块定义独立，未复用 NEXUS 四模块；
- [ ] 节点、模块、关系的仓库绑定全部通过 Schema 1.4 校验；
- [ ] 没有运行时证据的关系没有被标成 `runtimeVerified`；
- [ ] 跨仓库关系全部有 `interfaceEvidence` 与复核记录；
- [ ] NEXUS 回归数字不变；
- [ ] 真实 CRM 数据没有进入公开构建；
- [ ] Windows 实机验收状态如实标注（未做就是待验收）；
- [ ] 备份使用新文件名与独立目录，未覆盖 P1.3/P1.4 备份。

---

## 6. 明确不做

- 不扫描 CRM 或 Electron；
- 不按目录/命名相似自动生成跨仓库边；
- 不把 CRM 模块塞进 NEXUS 四模块；
- 不把同一 Git 仓库当成同一运行时；
- 不上传 CRM 内部代码、符号或路径到云端模型；
- 不修改其他 Agent 正在施工的 NEXUS 工作树；
- 不自动建立远程 Git 仓库。
