## 2. Graph Projection 设计与实现

### 2.1 数据流

```text
ATLAS 标准数据集（本地导入）
  → 关系筛选与聚合（projection.ts）
  → 模块 / 文件 / 符号星图布局数据
  → Canvas 2D（AtlasScene / ProjectionCanvas）
```

Canvas 不读取 Graphify 原始 `graph.json`，也不读取 ATLAS 节点数组做逐帧计算。`projection.ts` 是唯一投影入口。

### 2.2 聚合规则

- 模块节点固定为四个，来自 `dataset.modules`。
- 模块边只统计 **主模块不同** 且两侧都是 `scope=product` 的关系；Canvas 等支撑成员不会重复算作模块节点。
- 同一条边保留全部底层关系的 ID、类型、审核方式、状态、源码定位和方向，聚合只用于绘制。
- **没有证据就不画边**。演示数据返回零条真实边；当前快照没有 Canvas 主模块边，也没有跨模块 INFERRED 边，界面不会补线。
- 模块对按方向保留：`语音→数据 25` 与 `数据→语音 10` 是两条不同方向的边。

### 2.3 证据线型

| 证据类型 | 主画布 | 投影画布 |
| --- | --- | --- |
| Graphify 直接提取 | 青灰实线 | 青灰实线 |
| Graphify 推断 | 琥珀虚线 | 琥珀虚线 |
| AI 源码复核 | 紫色实线 + 菱形 | 紫色实线 + 菱形 |
| 独立人工审核 | 绿色双线 | 绿色双线 |
| 仍有待核实 | 红色点线叠加 + `?` | 红色点线叠加 + `?` |
| 中枢连接 / 星点 / 轨道 | 橙色构图 | 背景装饰 |

真实连线不运行光流粒子，避免被误读为运行时调用方向。真实边保留计数与待核实标记；在 1440p 左侧列空间不足时，计数徽标会沿边移向目标模块，而不是压在模块索引上。

### 2.4 缓存与节点上限

- 模块投影按 `AtlasDataset` 对象缓存在 `WeakMap` 中，只构建一次。
- 文件 / 符号投影按数据集对象 + 焦点缓存；切换层级或筛选时才重建。
- 当前上限：模块 4、文件 9（6 个本模块文件 + 3 个关联文件）、符号 14（10 + 4）个节点；边最多 48 条。
- 未显示的节点与边给出数量说明，不假装完整渲染 1,390 个节点。

### 2.5 当前快照结果

| 方向 | 关系数 | 证据构成 |
| --- | --- | --- |
| 语音交互 → 经营数据展示 | 25 | 直接提取 25；待核实 25 |

第一轮场景：**语音提问：从麦克风到覆盖层**。

| # | 步骤 | 来源 |

| 1 | 麦克风采集 | `VoiceMicrophone` |
| 2 | 会话状态机 | `sessionReducer` |

## 10. 已知缺口与下一轮建议

1. 当前快照只有 3 个有向模块对；Canvas 没有主归属节点；跨模块没有 INFERRED 边。不要为了视觉丰满补线。
2. 0 条独立人工审核；13 条 AI 复查关系仍不能替代人工签字。
3. 文件/符号投影是有限子图（9 / 14 节点），未显示的文件与符号需要进入关系探索或调整层级。
4. 路径最多 6 步，只返回一条无向静态路径；不保证唯一，不证明运行时顺序。
5. 流程只有一个语音场景，2 个衔接是缺口；需要更多源码证据或旧快照补证才能扩展。
6. 1440p 左侧列空间较紧；真实边徽标会向目标模块偏移，某些边在短视口下不显示计数徽标。
7. 4K、Windows、Edge 仍未实机验收。
8. 本地流程场景不进入仓库；迁移机器需要携带 `.flows.json` 或已附加流程的 `.atlas.json`。

下一轮建议优先：补充独立人工审核、确认跨进程语音链路的真实运行时关系、评估是否需要更多流程场景，以及在 Windows / Edge 上做一次完整验收。P1.2 在此停止。
