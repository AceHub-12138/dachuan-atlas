# DACHUAN ATLAS · P0.1 视觉优化记录

- **日期**：2026-10-20
- **版本**：v0.1.1 / P0.1
- **性质**：在既有 P0 原型上的定向视觉与动效优化
- **数据性质**：所有系统关系、模块信息、统计与技术画像仍为模拟数据

---

## 1. 本轮目标与边界

本轮只优化既有 P0 的视觉质量，不新增业务页、不改变三级交互、不接入真实数据或 Graphify / MCP / Agent Skill。

| 目标 | 实现方向 |
| --- | --- |
| 镜头空间感 | 前后景不同速度的星尘、相机速度拖影、收缩的到达光圈、NEXUS 星系连续放大为模块中枢、模块沿弧线展开 |
| 动态能量感 | 核心内部反向旋转能量虹膜、双层呼吸光晕、更长流星尾迹、关系线双段光尾与焦点脉冲 |
| 模块星系层级 | 每个模块增加两条微型轨道与三颗局部卫星，按前后景分层绘制 |
| 阅读清晰度 | 节点名称与说明提亮、暗态邻居保留最低可见度、标签局部底衬、详情面板辅助文字整体提升对比度 |
| 性能 | 使用同一设备、同一浏览器、同一测量方法做 P0 / P0.1 对照；不牺牲 60 FPS 目标与失焦降载 |

---

## 2. 修改范围

### 2.1 镜头与转场

- 星空由单一屏幕层扩展为 **远景 / 中景 / 近景** 三层视差；相机推进时三层以不同幅度平移和径向扩张。
- 新增少量柔焦前景尘埃，移动幅度大于星层，建立明显的前后景关系。
- 相机位移速度驱动短暂、低密度的星点拖影；只在层级切换期间出现，静止时完全消失。
- 进入 NEXUS 时新增收缩的“到达光圈”与刻度环；返回时自然反向扩张。
- NEXUS 星系本体不再与模块中枢做简单交叉淡化：系统本体延迟退场，中枢从 0.70 倍连续放大到 1.00 倍，模块沿弧线从枢纽展开。
- 模块关系线随模块展开进度生长，不再提前显示完整连接。
- 首页 / 模块层文字改为分层退场与入场：旧文字先在 170 ms 内退出，新文字延迟 190 ms 后淡入；消除转场中的标题叠字。

### 2.2 能量与节点动效

- 核心内部新增两组反向旋转的能量弧、三颗带短尾迹的内部能量微粒，以及缓慢旋转的分段外环。
- 核心光晕改为双频呼吸，避免机械的单频缩放；内部亮丝数量减少、亮度降低，保留能量感但减少“划痕感”。
- 三个系统星系、NEXUS 中枢与四个模块都加入不同相位的呼吸光晕。
- 流星尾迹加长到 160–320 px 级别，使用双层渐变与三颗微弱尾渍，单次最多 2 颗；仍明确属于背景装饰。
- 关系线光点增加双段尾迹；焦点连接使用 6 个光点与额外的大光波，非焦点连接保持可见但不抢焦点。
- 模块外圈增加 12 颗程序化卫星与 8 条微轨道，并按轨道前后关系分两次绘制，形成局部星系的遮挡层次。

### 2.3 装饰节点语义分离

- 卫星与微轨道定义在独立的 `MODULE_DECORATIONS` 数据中，不进入 `relations`、命中区域、tooltip 或详情数据。
- 另有 `DECORATIVE_LAYER_POLICY` 明确声明：装饰层不可交互、不属于模拟架构关系。
- About 面板加入中文说明：星尘、流星、模块外圈微卫星与细轨道均为程序化装饰，不代表数据传输或真实架构关系。

### 2.4 阅读清晰度

- 主要模块名称、模块说明、系统状态、核心说明文字整体提亮。
- 暗态邻居不再降到接近消失：系统星系最低保留 0.68，模块最低保留 0.58。
- 为系统标签、模块标签、中枢标签与核心说明增加缓存的局部暗色底衬，减弱核心光晕对文字的冲刷。
- 详情面板的模块序号、关联说明、技术信息、声明文字整体提升对比度与字号；面板底色略加深，保持半透明玻璃质感。
- 调整焦点层级：仍以橙色/暖色为视觉重心，没有把所有文字统一改成高亮白色。

### 2.5 涉及文件

- `src/data/atlas.ts`：装饰轨道与卫星数据、装饰层声明。
- `src/scene/AtlasScene.ts`：镜头、星空、到达光圈、核心、节点呼吸、流星、关系光流、卫星、标签底衬、暗态与文字对比。
- `src/App.tsx`：首页 / 模块层分层退出与入场，非活动层 `inert` / `aria-hidden`。
- `src/styles/scene-ui.css`、`src/styles/overlays.css`、`src/styles/base.css`：转场时序、详情面板与辅助文字对比、动效模式适配。
- `src/components/AboutDialog.tsx`：P0.1 范围与装饰层声明。
- `docs/`、`README.md`：P0.1 记录、截图与录屏更新。

未修改 CRM / ERP、NEXUS 或 Electron 项目；未新增任何依赖。

## 4. 性能对照

### 4.1 环境

- Apple M1 Ultra / 64 GB / macOS 15.7.8
- ZCode 内置 Chromium 146.0.7680.80 / Electron 41.0.3
- 测试显示器 1920×1080，100 Hz；DPR = 1
- 同一构建方式、同一浏览器、同一采样脚本；P0 基线在修改前采集

### 4.2 Canvas 绘制耗时对照

数据为页面内 `requestAnimationFrame` 与 `AtlasScene` 绘制计时。P0.1 数据取多次 1 秒窗口的中位值，括号内为部分波动范围。

| 场景 | 分辨率 | P0 平均 / p95 | P0.1 平均 / p95 | P0.1 rAF FPS | P0.1 95% 帧间隔 |
| --- | --- | --- | --- | ---: | ---: |
| 首页，完整动效 | 1920×1080 | 0.89 / 1.7 ms | 1.06 / 2.3 ms（1.04–1.11 / 2.1–2.5） | 99.8–100.2 | 11.9 ms |
| 首页 → NEXUS 转场 | 1920×1080 | 1.19 / 2.0 ms | 0.96 / 2.1 ms（0.92–1.05 / 1.2–2.3） | 99.8–100.1 | 11.9 ms |
| 语音交互详情 | 1920×1080 | 1.14 / 2.9 ms | 0.91 / 1.8 ms（0.84–1.03 / 1.0–2.5） | 99.9–100.2 | 11.9 ms |
| 首页，完整动效 | 2560×1440 | 1.31 / 2.3 ms | 1.22 / 2.7 ms | 100.1 | 11.9 ms |
| 首页，完整动效 | 3840×2160 | 0.74 / 0.8 ms | 0.86 / 1.0 ms（波动至 1.24 / 2.8） | 99.9–100.1 | 11.8 ms |
| 首页 → NEXUS 转场 | 3840×2160 | 1.13 / 2.4 ms | 0.88 / 1.0 ms | 100.1 | 11.9 ms |

### 4.3 结论与过程修正

- 1080p 首页的平均 Canvas 绘制增加约 0.17 ms；其余场景在运行波动范围内，没有出现持续退化。
- 所有场景仍受 100 Hz 显示器上限约束；95% 帧间隔最高 11.9 ms，低于 60 FPS 的 16.7 ms 预算，仍有明显余量。
- 中途发现 4K 转场在“全屏文字层 blur”期间会掉到约 95 FPS；移除全屏滤镜、保留位移与透明度转场后恢复 100.1 FPS。此修正已包含在最终代码中。
- 静态模式停止连续 rAF；低动态约 100 FPS；失焦约 19.6 FPS。

> 性能数字只对本机、本浏览器、本测量方法负责。Canvas 绘制耗时不等同于完整 GPU 合成帧时间，也没有使用专业 GPU Trace 工具。
