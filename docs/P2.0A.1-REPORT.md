## 1. 本轮结论

P2.0-A.1 完成了六项加固：

1. **partial 策略分叉**：缺失证据可以在显式 `--allow-partial` 下保持 `partial`；
   哈希、字节数、提交、仓库身份、时间、路径与符号链接冲突一律硬失败，
   `--allow-partial` 不能再绕过。
2. **独立 Git 历史核实**：新增 `tools/git-provenance.mjs`，只读核对提交是否存在、
   是否为 commit 对象、清单文件是否与历史树逐字节一致。清单内部一致与 Git 历史
   核实分别记录，`complete` 只在两者都通过时为真。
3. **节点统计可解释**：新增 `internalNodes / assignedNodes / unassignedNodes /
   multiModuleNodes`，并把 12 = 11 内部 + 1 外部、9 + 2 产品归属写成诊断信息与断言。
4. **安全边界补测**：路径穿越、符号链接逃逸、`public/`/`dist/`/`.git/`/
   `local-data/nexus/` 写入、成对写入回滚、CLI 无网络导入。
5. **隐私与分享分离**：审计报告明确记录 `privacyPassed`、`containsInternalSymbols`、
   `publicShareable=false`，三者不再混为一谈。
6. **完整回归与封存**：NEXUS 基线保持不变；新增独立 bundle 与隔离恢复报告。

## 3. 任务一：partial 导入策略

### 3.1 分类

`src/architecture/import-provenance.ts` 现在把来源问题分成两类：

| 类别 | 例子 | 默认 | `--allow-partial` |
| --- | --- | --- | --- |
| 缺失证据 | 缺少清单、缺少报告、清单为空、提交只来自报告、没有 Git 仓库、Git 只能对应部分文件 | 失败 | 允许，状态 `partial` |
| 矛盾证据 | SHA-256 不匹配、文件缺失、字节数/文件数冲突、提交冲突、仓库/系统冲突、时间冲突、路径越界、符号链接、Git 提交不存在/非 commit | 失败 | **仍然失败** |

### 3.2 关键修复

P2.0-A 中 `tamperedFileHash + --allow-partial` 可以生成输出。现在：

- `tools/import-safety.mjs` 的 `verifyManifestFiles()` 返回
  `integrity='mismatch'` 与 `hardFailure=true`；
- CLI 在来源核对阶段直接抛出“这是矛盾证据，--allow-partial 不能绕过”；
- `evaluateImportProvenance()` 收到 `manifestIntegrity='mismatch'` 时也会抛出
  `GRAPHIFY_MANIFEST_MISMATCH`，库级调用同样不能被绕过；
- 生成时间/扫描时间冲突从 warning 改为硬错误
  `GRAPHIFY_PROVENANCE_TIME_CONFLICT`；
- Git 核实 `failed` 是硬错误 `GRAPHIFY_GIT_HISTORY_FAILED`。

### 3.3 失败不污染

- 数据集与审计报告先写临时文件，再逐个替换；
- 任一写入失败会恢复旧文件、删除临时文件；
- 输出不得与 Graphify 输入目录、profile、`public/`、`dist/`、`.git/`、
  `node_modules/`、`local-data/nexus/` 重合；
- 测试验证了“旧输出内容保持不变、没有报告文件、没有 `.tmp`/`.bak` 残留”。

## 4. 任务二：本地 Git 历史核实

### 4.1 实现

新增 `tools/git-provenance.mjs`，只调用只读 Git plumbing：

```text
git rev-parse --verify <sha>^{commit}
git cat-file -t <sha>
git ls-tree -r -z --full-tree <sha>
```

对每个清单文件计算 Git blob 对象 ID：

```text
SHA-1("blob <byte-length>\0" + 文件内容)
```

再与历史树中的 blob ID 比较。**不读取工作树、不 checkout、不 fetch、不执行钩子。**

### 4.2 分开报告

`snapshot.importStatus` 不再单独由清单自洽决定：

| 清单内部一致性 | Git 历史 | `complete` | 导入状态 |
| --- | --- | --- | --- |
| verified | verified | 是 | `complete` |
| verified | partial | 否 | `partial` |
| verified | not_attempted | 否 | `partial` |
| partial | 任意 | 否 | `partial` |
| mismatch | 任意 | — | 硬失败 |

审计 JSON 明确包含：

```json
{
  "provenance": {
    "manifestConsistency": "verified",
    "historyVerification": { "status": "verified", "matchedFiles": 8 },
    "separation": {
      "completeRequiresBoth": true,
      "note": "清单内部一致与 Git 历史核实分别记录；complete 只在两者都通过时为 true。"
    }
  }
}
```

### 4.3 合成 Git 验证

使用临时 `git init` 仓库与固定作者/时间生成合成提交：

- 提交是 commit 对象且 8/8 文件一致 → `verified`；
- 不存在的提交 → `failed`，不能降级；
- annotated tag 对象 → `failed`，不能冒充 commit；
- 快照文件被改写 → `partial`，记录具体路径；
- 快照缺失文件 → `partial`，记录 `missingInSnapshot`；
- 快照多出文件 → `partial`，记录 `snapshotFilesNotInManifest`；
- 快照符号链接 → `partial`，记录 `symlinksInSnapshot`；
- Git 同目录有清单外文件 → 仍可 `verified`，但记录
  `gitFilesNotInManifest`，不伪造冲突。

## 5. 任务三：节点统计分区

合成 CRM 的 12 个节点不是“9 + 2 + 1 丢失”，而是：

```text
12 个已导入节点
= 11 个内部节点（product 11 + test 0 + tooling 0）
+ 1 个外部节点（zod 依赖）
```

产品模块主归属：

```text
11 个产品节点 = 9 个已归类 + 2 个未分类（shared/id.ts、shared/config.ts）
```

全部节点的模块主归属：

```text
12 = 9 个已归类 + 3 个未归类（2 个产品节点 + 1 个外部节点）
```

新增 `diagnostics.counts`：

| 字段 | 含义 |
| --- | --- |
| `internalNodes` | `nodes - externalNodes` |
| `assignedNodes` | 全部节点中有主模块归属的数量 |
| `unassignedNodes` | 全部节点中没有主模块归属的数量 |
| `multiModuleNodes` | `moduleIds.length > 1` 的数量；重叠维度 |
| `modulesAssigned` / `modulesUnassigned` | 仅产品节点，分别对应 9 / 2 |

`GRAPHIFY_NODE_PARTITION` 诊断写出完整公式；测试断言：

```text
nodes = internalNodes + externalNodes
internalNodes = productNodes + testNodes + toolingNodes
productNodes = modulesAssigned + modulesUnassigned
nodes = assignedNodes + unassignedNodes
```

没有修改合成原始节点，也没有为了让数字相等而改动归类规则。

## 6. 任务四：安全边界

### 6.1 输入

- 清单路径必须是仓库相对路径；`..`、绝对路径、盘符路径、`~`、`:`、NUL 均拒绝；
- `source-snapshot` 目录本身或内部任何符号链接都使清单一致性进入 `mismatch`；
- 清单文件经 `lstat` 与 `realpath` 双重检查，真实路径必须在 `source-snapshot` 内；
- `graph.json`、`snapshot-manifest.json`、`GRAPH_REPORT.md` 不得通过符号链接
  指向输入目录之外。

### 6.2 输出

- `public/`、`dist/`、`.git/`、`node_modules/`、`local-data/nexus/` 一律拒绝；
- 真实 CRM 只能写 `local-data/crm/` 或项目外目录；
- 拒绝目标本身是符号链接；父目录符号链接会解析真实路径后再判断；
- 拒绝写入 Graphify 输入目录或覆盖 profile；
- 数据集与报告成对写入，失败回滚。

### 6.3 网络与隐私

- `tools/import-crm.mjs`、`git-provenance.mjs`、`import-safety.mjs` 没有
  `node:http/https/net/dns/tls/dgram` 导入，没有 `fetch()` 或 `http.request`；
- 用 `NODE_DEBUG=net,http,https,dns,tls` 运行完整 dry-run，没有网络日志；
- 管线 `modelCallsFromPipeline=0`。

审计报告把三个概念分开：

| 字段 | 本轮合成结果 | 含义 |
| --- | --- | --- |
| `privacyPassed` | `true` | 没有绝对路径/凭据字段 |
| `containsInternalSymbols` | `true`（11 个） | 输出仍含内部符号、相对路径与关系 |
| `publicShareable` | `false` | 不能因为隐私体检通过就公开 |
