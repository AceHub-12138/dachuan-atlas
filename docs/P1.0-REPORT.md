## 3. 数据适配架构

### 3.1 分层

```text
Graphify POC 原始产物
  graph.json / snapshot-manifest.json / GRAPH_REPORT.md
            │
            ▼
A. Graphify 原始层（只读，不进入前端）
            │  tools/import-graphify.mjs
            │  版本检查、清单校验、路径归一化、脱敏、统计
            ▼
B. ATLAS 标准架构数据（atlas.architecture v1.0.0）
  public/architecture/nexus/nexus-2026-10-20-2584284.atlas.json
            │
            ├── C. 中文解释与人工审核（嵌入节点/模块）
            │     displayName / responsibility / review / module evidence
            │
            └── D. 前端可视化布局（保持独立）
```

Canvas 只读取 D 层。B 层不进入 `AtlasScene.ts`，不参与逐帧绘制。

### 3.3 为什么不让 Canvas 直接读 Graphify

- Graphify 的 `community` 是聚类编号，不是业务模块；
- 原始图没有 1,390 个节点的布局信息，直接绘制会破坏 P0.1 视觉与性能；
- 原始字段（绝对路径、外部引用、未落边调用）需要清洗与审核；
- 前端需要稳定的审核状态、快照元数据与错误处理，而原始 JSON 没有这些语义。

## 4. ATLAS 标准 Schema

完整定义见 [ATLAS-SCHEMA.md](architecture/ATLAS-SCHEMA.md)。核心约束：

- `schemaId = 'atlas.architecture'`，`schemaVersion = '1.0.0'`；只接受主版本 1。
- 节点逻辑 ID 为 `nexus:<repo-relative-path>#<symbol>`，**不含提交 SHA**；同名符号用父级作用域或行号消歧。
- 关系保留 `EXTRACTED / INFERRED / AMBIGUOUS`，并独立记录 `review.status`。
- 快照强制 `history: true`，记录完整提交、生成时间、导入时间、Graphify 版本、清单状态。
- 模块记录规则、说明、证据、统计与审核状态。
- 诊断记录无效节点、重复、悬空、脱敏、未落边调用与覆盖盲区。

导入契约：

| 场景 | 行为 |
| --- | --- |
| ATLAS 标准数据导入 | 严格：重复节点、悬空关系、绝对路径、错误版本均拒绝 |
| Graphify 原始数据导入 | 容错：单节点/单边异常跳过并计数；版本不符拒绝 |
| 缺少 manifest | 允许导入，`commit = unknown`、`importStatus = partial`，界面显示“未知” |
| 清单哈希不匹配 | CLI 默认失败；`--allow-partial` 可继续并标记 partial |
| 快照 fetch 失败 | 回退演示数据 + 中文提示；Canvas 继续运行 |

## 6. 中文模块映射

完整证据见 [NEXUS-MODULE-EVIDENCE.md](architecture/NEXUS-MODULE-EVIDENCE.md)。

| 模块 | 主节点 | 支撑 | 内部关系 | 跨模块 | 已核实关系 | 待核实关系 | Community | 状态 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 经营数据展示 `data` | 211 | 0 | 322 | 81 | 4 | 318 | 23 | 已核实 |
| 语音交互 `voice` | 530 | 0 | 1,190 | 35 | 4 | 1,186 | 43 | 已核实 |
| 动画调度 `animation` | 68 | 0 | 132 | 13 | 3 | 129 | 3 | 已核实 |
| Canvas 渲染 `canvas` | 0 | 58 | 86 | 68 | 2 | 84 | 0 | 部分核实 |

> “跨模块”为每个模块的关联边数，存在两侧各计一次；按主模块去重后的跨模块关系为 48 条：`data ↔ voice` 35、`animation ↔ data` 13。Canvas 的 68 条来自支撑文件的交叉归属，不能与前两者相加当总量。

### 6.1 Community 不是模块

- 语音模块横跨 **43 个 Community**；
- `Community 31` 只有 **17 个节点**，全部是 `services/voice-orchestrator/` 下的编排、监听、鉴权与 HTTP 输入代码；
- 若直接把 Community 31 命名为“语音交互”，会漏掉 500 多个节点，也会把不同职责强行合并。

因此数据集保留 `community` 原值，但模块判定只用路径与文件职责。

### 6.2 Canvas 为什么是“部分核实”

历史快照没有独立 Canvas 目录或入口。实际 Canvas 2D 绘制分布在：

- `src/components/overlay/JarvisCore.tsx`（语音覆盖层粒子核心）；
- `src/lib/voice/params.ts`（投影与粒子数学）；
- `src/components/screen/motion/useSceneMotion.ts`（大屏背景粒子）；
- `src/components/screen/ScreenStage.tsx`（canvas 容器）。

Graphify 没有生成 `getContext` / `fillRect` / `CanvasRenderingContext2D` 节点。源码能证明 Canvas 绘制存在，但不能证明完整调用网络，所以没有虚构主模块，只标记 4 个支撑文件，状态 `partially_verified`。

### 6.3 历史快照缺失组件

`GsapTickerOwner` 不在本快照中。本轮没有读取 NEXUS 当前工作区，也没有把它补进旧快照。动画模块的结论只基于 `MotionDirector`、`GsapScene`、`MotionProvider`、`useSceneMotion`、`useReducedMotion`、`MotionConfig`。

## 8. 跨平台导入与导出

### 8.1 命令行（macOS / Windows）

```bash
# macOS / Linux
npm run import:graphify -- --graphify "../graphify-poc" \
  --expect-commit 2584284e3e7b994d0510d9d53b2a302e3aa740bc

# Windows PowerShell
npm run import:graphify -- --graphify "D:\path\to\graphify-poc" `
  --expect-commit 2584284e3e7b994d0510d9d53b2a302e3aa740bc
```

CLI 行为：

- 接受目录或直接指向 `graph.json`；
- 自动读取 `snapshot-manifest.json`、`GRAPH_REPORT.md`；
- 默认强制校验清单；不一致时失败，`--allow-partial` 可继续并标记 partial；
- 支持 `--out`、`--report`、`--generated-at`、`--repository-name`、`--dry-run`；
- 输出数据集后立即按标准 Schema 重新解析，确认可再次导入；
- 审计报告写入 `docs/architecture/nexus-import-report.json`。

### 8.2 浏览器导入（不需要 Bash）

右上角数据徽标 → 架构数据面板 → 导入：

- 一个 ATLAS 标准 JSON；或
- `graph.json` + 可选的 `snapshot-manifest.json`。

文件只在本地浏览器内读取，不上传。可处理：

- 缺少 manifest（提交标记 unknown，partial）；
- 非法 JSON；
- 不兼容版本；
- 非 ATLAS/Graphify 文件；
- 超过 50 MB 的文件。

> 本环境的内置浏览器不支持文件选择器上传，因此浏览器按钮的**点击**路径未在本轮实机执行；文件解析、导入、错误分支由单元测试覆盖。CLI 的同一套核心已在真实快照上执行。

### 8.3 导出

- 面板“导出当前标准数据”生成 `.atlas.json` 下载；
- 文件名包含提交短 SHA 与日期；
- 导出后重新导入，节点、关系、审核状态与统计保持一致（单元测试通过）；
- 导出文件包含内部符号名与相对路径，界面明确提示不要公开上传。

### 8.4 路径与隐私

- 所有路径统一为 `/` 分隔；
- 拒绝 `/Users/...`、`C:\...`、UNC、`~`、`..`、含 `:` 的路径；
- 由绝对路径 slug 化的外部节点标签替换为“外部路径引用（已脱敏）”；
- 源仓库绝对路径不写入数据集；
- 浏览器错误与 CLI 错误不回显绝对路径；
- 数据包移动后不依赖原 Mac 目录结构。

## 13. P1.1 接入现有星系界面的建议

1. **模块节点直接显示映射状态**：在 `AtlasScene` 的模块标签旁增加“已核实 / 部分核实 / 待核实”小标记，数据来自 B 层模块记录；不改变节点位置与动画。
2. **点击模块进入真实详情**：把经营数据、动画、Canvas 的占位提示替换为真实模块详情；每个详情首屏只展示模块统计、3–5 个证据符号和审核状态，避免一次渲染数百节点。
3. **关系下钻与筛选**：在详情中增加 `EXTRACTED / INFERRED / 已核实 / 待核实` 筛选；点击关系显示 `from → to`、类型、置信度、`file#Lline` 与审核记录。
4. **保持 Canvas 与数据解耦**：Canvas 继续只读 D 层；真实节点用面板/抽屉/局部星系呈现，不要把 1,390 节点直接铺到首页。
5. **审核工作流独立**：把人工审核记录放在单独文件（如 `review/nexus.json`），不要改写 Graphify 原始产物；导出时合并为 ATLAS 数据集，保留 `reviewer/reviewedAt/note`。
6. **Schema 升级到 1.1**：增加 `annotations`、`reviewEvents`、`moduleAssignments` 的独立分区，避免机器数据与人工判断混在同一数组里。
7. **CRM / Electron 接入前先做范围审计**：确认仓库、提交、排除规则与敏感路径；在数据完成前继续显示“尚未接入真实架构数据”。
8. **性能护栏**：快照仍按需加载；模块详情懒加载该模块节点；关系图按需聚合到文件/符号层；不在 rAF 中做任何数据计算。
9. **跨平台验收**：在 Windows 实机执行一次 CLI + 浏览器导入 + 导出重导入；确认盘符路径、反斜杠与文件选择器行为。
10. **视觉统一优化留到最后**：等 P1.1 信息架构稳定后，再统一处理面板密度、字号、色阶与动效节奏，避免边做功能边改视觉。
