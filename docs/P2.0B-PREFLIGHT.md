# DACHUAN ATLAS · P2.0-B 真实 CRM 接入前置清单

> 状态：**未开始**。本文是进入真实 CRM 接入前必须由用户确认的门槛，不是授权本身。  
> 日期：2026-10-21  
> 适用 Schema：`atlas.architecture` 1.4.0  
> 前置轮次：P2.0-A（仅合成数据验证）

---

## 1. 一句话结论

P2.0-B 只能接入**一个由用户明确指定的 CRM 历史快照**。在用户书面确认扫描范围、
Graphify 产物、提交与仓库身份之前，不读取真实 CRM，不调用云端模型分析真实源码，
不生成 NEXUS ↔ CRM 连线。

---

## 2. 必须由用户提供或授权

### 2.1 扫描与数据范围

- [ ] 明确 CRM 本地目录（绝对路径只在本机使用，不写入数据集或公开文档）。
- [ ] 明确允许读取的子目录 / 排除目录（例如构建产物、密钥、客户数据）。
- [ ] 明确 Graphify 已在该目录生成历史快照，而不是当前工作树临时扫描。
- [ ] 确认 `source-snapshot/` 是生成图谱时的快照，且可逐文件校验。

### 2.2 仓库与提交

- [ ] `repository.id='crm'`、`system='crm'`、展示名称。
- [ ] 完整 40 位提交 SHA，与 `snapshot-manifest.json`、`GRAPH_REPORT.md` 一致。
- [ ] 扫描时间与生成时间（缺少时明确接受 `partial`）。
- [ ] 确认该提交不是当前工作树、不是未提交改动、不是重新生成的替代物。

### 2.3 CRM 模块定义

- [ ] CRM 自己的模块 ID（不得使用 `data / voice / animation / canvas`）。
- [ ] 每个模块的路径规则（前缀必须 `/` 结尾）或职责证据。
- [ ] 模块中文名、摘要、职责、缺口与代表组件。
- [ ] 模块定义的审核方式、审核人、日期与证据；没有复核就保持 `unverified`。
- [ ] 明确接受：无法归类的节点保持未分类，不为了星图完整强行归类。

### 2.4 运行时边界

- [ ] 服务端、Web 前端、桌面端、定时任务/worker 的实际边界。
- [ ] 每个边界判断的证据（启动配置、构建入口、部署记录等），不是目录名猜测。
- [ ] 没有证据时全部保持 `runtimeScope=unknown`。
- [ ] 只有 trace、日志、协议测试、集成测试或运行时观察能支撑
      `runtimeVerified=true`；AI 源码复核不够。

### 2.5 跨仓库接口

- [ ] NEXUS ↔ CRM 的接口清单：API 契约、协议 schema、包依赖、配置绑定。
- [ ] 每条接口的复核记录与证据位置。
- [ ] 没有接口契约与复核记录时，不建立已确认跨仓库连线。
- [ ] 未确认候选单独保存，不能进入 `confirmedCrossRepositoryRelations()`。

### 2.6 人员与合规

- [ ] 指定架构审核人；AI 复核与人工审核分开记录。
- [ ] 确认 CRM 数据允许在本机进入 ATLAS 本地数据目录。
- [ ] 确认**不**把真实 CRM 源码、符号、路径、Graphify 产物或快照发送给任何云端模型、
      第三方服务或公共仓库。

---

## 3. 数据传输边界（重要）

P2.0-A 的 CLI 是本地确定性代码，不调用网络或云端模型。  
但施工 Agent 本身运行在云端模型上：**如果让 Agent 读取真实 CRM 源码、内部符号、
Graphify 原始产物或路径信息，这些内容会进入模型调用上下文。**

因此 P2.0-B 必须二选一：

1. **本地人工执行**：用户在本机运行 `npm run import:crm`，只把脱敏后的统计/报错
   （不含源码、符号、路径）交给 Agent 复核；或
2. **明确授权 Agent 接触真实数据**：用户书面确认数据可以发送给当前模型服务商，
   并接受相应的数据保留/合规风险。

未得到明确授权前，Agent 不得读取真实 CRM 目录，也不得把真实数据作为提示词内容。

## 4. P2.0-B 执行门槛

只有以下全部成立才能标记“CRM 已接入”：

- [ ] 用户书面确认扫描范围、Graphify 产物与 profile；
- [ ] CRM 快照有真实提交 SHA，或用户明确接受 `unknown/partial`；
- [ ] `npm run import:crm` 在本机通过，输出为 `complete`（或经用户确认的 `partial`）；
- [ ] 模块 ID、路径规则、审核记录独立于 NEXUS；
- [ ] 未分类节点数量与原因可解释；
- [ ] 没有运行时证据的关系全部保持 `unknown` / `runtimeVerified=false`；
- [ ] 跨仓库关系全部有 `interfaceEvidence` 与复核记录；
- [ ] NEXUS 回归保持 1,390 节点 / 3,170 关系 / 四模块 / 3 组模块对 / 48 条模块间关系 /
      7 个概念步骤 / 4 个静态衔接 / 2 个缺口；
- [ ] 真实 CRM 数据未进入 `public/`、`dist/`、Git 或云端；
- [ ] 浏览器导入安全边界与仓库切换方案已审核；
- [ ] 备份使用新文件名与独立目录，未覆盖 P1.3/P1.4 备份；
- [ ] Windows 实机与异机备份状态如实标注（未做就是待验收）。

---

## 5. P2.0-B 仍需开发的内容

P2.0-A 只完成数据层与本地 CLI。真实接入前还需要：

1. 仓库切换器 / 多仓库索引 UI；
2. CRM 模块星图的独立投影与布局（不能复用 NEXUS 四模块轨道）；
3. 跨仓库关系视图与候选隔离展示；
4. 真实 CRM profile 的审核工作流；
5. 运行时边界与接口证据的录入/复核界面（如需要）；
6. Windows 实机导入验证；
7. 异机 / 离线介质备份与恢复证据。

---

## 6. 明确不做

- 不扫描 CRM 或 Electron，直到用户授权；
- 不按目录/命名相似自动生成 NEXUS ↔ CRM 连线；
- 不把 CRM 模块塞进 NEXUS 四模块；
- 不把同一 Git 仓库当成同一运行时；
- 不把 Graphify 静态边当成运行时调用；
- 不上传真实 CRM 内部资料；
- 不修改其他 Agent 的工作树；
- 不自动建立远程 Git 仓库。
